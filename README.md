# VidGen — Omni Flash + Seedance 2 Pro

Сайт для генерации видео. Промпт, референсы, длительность, качество, соотношение сторон — те же окна, что на источнике, но запуск идёт через наш бэкенд.

## Как работает

Всё идёт через реальный API генерации:

1. бэкенд авторизуется в API источника (`http://160.30.161.35`)
2. если загружены референсы — они заливаются как картинки-референсы
3. отправляется команда генерации (та же, что жмёт кнопку Generate на источнике)
4. бэкенд поллит статус, ждёт `done`
5. видео скачивается к нам в `data/videos/` и отдаётся с нашего сайта

## Запуск

```
START.bat
```

или

```
node server.js
```

Откроется на `http://localhost:8080` (если порт занят — автоматически `8090`).
Порт и адрес источника переопределяются через `PORT` и `TARGET_URL`.

## Два режима (левая колонка)

- **🎥 Omni Flash** — движок `🎥 Veo 3 Free` (`server11`), модель `Veo 3.1 Fast`
  - длительность 4/6/8 сек → Veo (`server11`), 10 сек → `Gencpu Free`:
    `server7`/`Seedance 2.5 Lite` (повтор при OOM), фолбэк `server10`/
    `Gencpu 1.1` — реальные 10с, 720p, free 0d; Veo 10с не принимает,
    их же фронт зажимает до 8
  - 720p, 16:9 / 9:16 / auto
- **⚡ Seedance 2 Pro** — движок `⚡ Seedance 2.0 24/7` (`server2`)
  - модель: Standard (по умолчанию) / Fast / Lite
  - длительность 5/8/10/12/15 сек, 480p/720p

## 10 секунд в Omni Flash

Выбираешь `10 сек` → запрос уходит с настройками, как на панели источника
(720p, 16:9, Audio, 1 видео), но не на Veo, а в бесплатный кластер
**Gencpu Free** — Veo 10с физически не принимает (их бэкенд отвечает
`Server 11 hỗ trợ 4s, 6s, 8s`, их же фронт зажимает `10 → 8`).

**Цепочка отправки** (промпт один, просто разные движки по очереди):

| # | Кластер | Модель | Что происходит |
|---|---|---|---|
| 1 | `server7` | `Seedance 2.5 Lite` | основной путь — принимает 10с, 720p, free 0d |
| 2 | `server7` | то же | повтор через 60с — OOM на их GPU обычно проходит |
| 3 | `server7` | то же | ещё повтор через 60с |
| 4 | `server10` | `Gencpu 1.1` | только если `readyStreams > 0`; иначе пропускается (пустая очередь висит вечно) |

Каждая попытка: отправка → поллинг до 15 мин → при OOM/таймауте переход к
следующей. Статусы в UI честные (`submitting`, `pending_queue`, ...).

**Возможные исходы:**

- **done** — реальные 10с, 720p
- **error: «Gencpu Free (10с) сейчас недоступен — попробуй позже»** — их
  бесплатный кластер лежит (частая причина: `Máy chủ GPU Free ... quá tải bộ nhớ`
  — их GPU перегружен, колется «через несколько минут»). Тогда:

**Что делать, когда 10с недоступны:**

- позже повторить (их OOM проходит сам, 5–30 мин)
- или переключиться на **Seedance 2 Pro** — там 10с идут через пакетный
  токен `PAID_TOKEN` (env), не зависит от бесплатного кластера
- 4/6/8 сек на Veo обычно работают всегда — они на отдельном server11

## API-ключи (для внешних приложений)

Раздел **🔑 API-ключи** в интерфейсе: создание, копирование, отзыв ключей.
На телефоне (узкий экран, сайдбар скрыт) кнопки «🕒 История» и «🔑 API-ключи»
— в правом верхнем углу топбара.

Все `/api/*` маршруты (кроме `GET /api/config`) требуют ключ в заголовке
`X-Api-Key` или `Authorization: Bearer vg_...`. Для видео, которое тянет
`<video>`/скачивание, ключ передаётся в URL: `?key=vg_...`.

```bash
curl -H "X-Api-Key: vg_ваш_ключ" https://vidgen-kgpf.onrender.com/api/jobs
```

### Управление ключами (нужен web-ключ)

- `GET /api/keys` → `{keys:[{key, id, name, createdAt, lastUsedAt, disabled}], emergency:"vg_..."}`
- `POST /api/keys` body `{"name":"мой бот"}` → `{key, name}`
- `POST /api/keys/sync` body `{"keys":[{key, name, createdAt, lastUsedAt, disabled}]}` → `{ok, restored}` — восстановление списка после редеплоя
- `DELETE /api/keys/:key` → `{ok:true}` — отзыв, web-ключ и аварийный удалить нельзя (400)

### Аварийный ключ (всегда работает)

Один ключ зашит прямо в код `server.js` (`EMERGENCY_KEY`, можно переопределить
переменной окружения того же имени) и принимается сервером безусловно —
не зависит ни от `keys.json`, ни от секрета, ни от диска. Переживает любые
рестарты и редеплои. Значение показано в интерфейсе отдельной строкой
в разделе «🔑 API-ключи» и возвращается полем `emergency` в `GET /api/keys`.
Назначение — подстраховка для внешних приложений, когда-нибудь понадобится
пересоздать обычные ключи.

### Где хранятся ключи и что с ними бывает при рестарте

Ключи **не зависят от диска** — на Render free диск эфемерный и `data/`
стирается при каждом рестарте/редеплое:

- **web-ключ** берётся из переменной окружения `WEB_KEY` (пример в
  `render.yaml`) — не меняется никогда, пока задана
- **новые ключи** несут HMAC-метку от секрета (`WEB_KEY`/`KEY_SECRET` из
  окружения, локально `data/secret.txt`) и принимаются сервером даже когда
  `keys.json` утрачен — то есть работают вечно
- **список ключей** браузер хранит в `localStorage` и при загрузке страницы
  отправляет на `POST /api/keys/sync` — имена, даты и отзывы
  восстанавливаются автоматически
- **старые ключи** (созданные до внедрения HMAC-формата) после рестарта
  невалидны — их нельзя проверить без записи на диске. Восстанавливаются
  первым же открытием сайта (sync), а на случай недоступности есть
  **аварийный ключ** выше

Чтобы ничего не потерялось на Render: задайте переменную окружения
`WEB_KEY` в настройках сервиса (Render → Environment). Без неё в шапке
сайта появится предупреждение `⚠ ключи не сохранятся без WEB_KEY`.

Браузер чинится сам, без ручных действий:

- при ответе `401` фронт один раз перечитывает `/api/config` без кэша,
  сохраняет новый ключ и повторяет запрос уже с ним
- если ключ сменился, у всех `<video>` переписывается `?key=` в `src`
- если `/api/config` не ответил (холодный старт), используется ключ
  из `localStorage`, а не пустой

### POST /api/generate

```json
{
  "model": "omni",
  "targetModel": "Veo 3.1 Fast",
  "prompt": "лисёнок бежит по снежному лесу, кинематографично",
  "duration": 8,
  "resolution": 720,
  "ratio": "16:9",
  "audio": true,
  "refs": [
    { "filename": "face.png",
      "contentType": "image/png",
      "dataBase64": "data:image/png;base64,iVBORw0KGgo..." }
  ]
}
```

| поле | значения | что делает |
|---|---|---|
| `model` | `omni` \| `seedance` | выбор движка, обязателен |
| `targetModel` | см. таблицу ниже | конкретная модель |
| `prompt` | строка | обязателен, пустой → `400 prompt empty` |
| `duration` | omni: `4/6/8/10`, seedance: `5/8/10/12/15` | секунды |
| `resolution` | omni: только `720`, seedance: `480` \| `720` | качество |
| `ratio` | omni: `16:9` `9:16` `auto`; seedance: `16:9` `9:16` `1:1` `3:4` `4:3` `21:9` `auto` | кадр |
| `audio` | `true`/`false` (по умолчанию `true`) | звук |
| `refs` | до 9 штук | фото-референсы, есть → режим `i2v` |

**`targetModel` — точные значения:**

| `model` | допустимые `targetModel` | по умолчанию |
|---|---|---|
| `omni` | `Veo 3.1 Fast`, `Veo 3.2 Fast`, `Veo 3.1 Lite` (4/6/8с); при `duration: 10` — `Gencpu 1.1` (Gencpu Free) | `Veo 3.1 Fast` |
| `seedance` | `Seedance 2.0 Standard`, `Seedance 2.0 Fast`, `Seedance 2.0 Lite` | `Seedance 2.0 Standard` |

Неизвестное значение молча заменяется на модель по умолчанию (ошибка не будет).
Длительность omni `10` уходит в `Gencpu Free` (`server7`/`Seedance 2.5 Lite`,
фолбэк `server10`/`Gencpu 1.1`) — там разрешены 10с; Veo (`server11`) 10с
не принимает, их же фронт зажимает до 8.
Невалидный `duration`/`ratio` тоже заменяются на безопасный дефолт.

**Фото-референсы:** `refs` — массив до 9 объектов.
`dataBase64` — строка вида `data:<mime>;base64,<данные>` (то, что возвращает
`FileReader.readAsDataURL`), `filename` и `contentType` — любые.
Первая картинка считается кадром/персонажом. Если `refs` пустой или не
передан — генерация текст-в-видео (`t2v`), с картинками — `i2v`.

**Ответ:**

```json
{ "job": {
    "id": "jmwmjo3nz2639",        // <- id задачи, дальше опрашивать его
    "status": "pending",
    "stage": "new",
    "progress": 0,
    "keyLabel": "web",
    "hasVideo": false,
    "error": null,
    "createdAt": 1795031937935,
    "finishedAt": null } }
```

Ошибка на входе → `400 {"error":"prompt empty"}` или `400 {"error":"bad model"}`,
нет ключа → `401 {"error":"API-ключ не передан или недействителен (X-Api-Key)"}`.

### GET /api/jobs и GET /api/jobs/{id}

`GET /api/jobs` → `{"jobs":[ ... ]}` (новые сверху),
`GET /api/jobs/{id}` → `{"job": ...}`; нет такой или она не вашего ключа → `404 {"error":"not found"}`.

Поля задачи:

- **`id`** — идентификатор, он же имя файла: `/api/videos/{id}.mp4`
- **`duration`** — фактическая длительность: `4/6/8` для omni на Veo
  (`server11` — 10с их сервер отклоняет, см. ошибку ниже), `10` для omni
  при запросе 10 (уходит в `Gencpu Free`/`server7`, фолбэк `server10`),
  `5/8/10/12/15` для seedance
- **`requestedDuration`** — что вы запрашивали, если это не совпало с
  `duration` (теперь только при нестандартном запросе), иначе `null`
- **`status`** — итог: `pending`, любое промежуточное состояние источника
  (`queued`, `running`, `processing`...), `done` (видео скачано и лежит у нас)
  или `error`
- **`stage`** — что происходит прямо сейчас:

  | stage | текст в интерфейсе |
  |---|---|
  | `new` | очередь |
  | `account` | соединяемся с API |
  | `account_ready` | API подключён |
  | `upload_refs` | загружаем референсы |
  | `submitting` | отправляем генерацию |
  | `queued` / `pending_queue` | в очереди на источнике |
  | `running` | рендерим видео |
  | `target_done` | видео готово — скачиваем к нам |
  | `downloading` | скачиваем готовое видео |
  | `done` | готово |
  | `error` | ошибка |

- **`progress`** — 0…100
- **`error`** — текст ошибки, `null` пока всё хорошо
- **`hasVideo`** — `true` только когда mp4 реально лежит на диске.
  **Считать готовым можно только `status === "done" && hasVideo === true`** —
  статус `done` без `hasVideo` означает, что файл ещё доезжает
- **`keyLabel`** — имя ключа, создавшего задачу

`status: "done"` без `hasVideo` — промежуточное состояние, продолжайте опрашивать
(фронт делает это каждые 2.5 с).

### GET /api/videos/{id}.mp4

Отдаёт mp4 с поддержкой `Range`: `206 Partial Content` на `Range: bytes=...`,
`200` без него. Ключ — в заголовке или в `?key=`.

### Пример на curl

```bash
K="vg_ваш_ключ"
ID=$(curl -s -H "X-Api-Key: $K" -H "Content-Type: application/json" \
  -d '{"model":"omni","targetModel":"Veo 3.1 Fast","prompt":"a fox running","duration":8}' \
  https://vidgen-kgpf.onrender.com/api/generate | jq -r .job.id)

while true; do
  S=$(curl -s -H "X-Api-Key: $K" https://vidgen-kgpf.onrender.com/api/jobs/$ID)
  echo "$S" | jq -r '"\(.status) \(.stage) \(.progress)% \(.error // "")"'
  [ "$(echo "$S" | jq -r '.job.status')" = "done" ] && break
  sleep 5
done

curl -H "X-Api-Key: $K" -o out.mp4 https://vidgen-kgpf.onrender.com/api/videos/$ID.mp4
```

### Ограничения

- одновременно у одного ключа рекомендуется одна активная задача
- прерванная рестартом сервера задача получает `status:"error"` с текстом
  «сервер был перезапущен во время генерации — запустите заново»
- на бесплатном тарифе хостинга сайт засыпает: первый запрос после простоя
  идёт 40–60 секунд

## Лимиты источника — НЕ наше ограничение (проверено живьём)

Все счётчики ниже действуют **на один аккаунт источника**. Наш сервер для
каждой генерации сам регистрирует свежий аккаунт (временный email), поэтому
на нас они не влияют:

- **Veo 3 Free: 5/день** — на аккаунт; каждый запуск = новый аккаунт = новый лимит
- **Gencpu Free: 10/день** — так же, 10 на новый аккаунт (для Omni Flash 10с)

Что реально может остановить генерацию (от аккаунтов не зависит):

- **OOM на их GPU** (`server7`) — глобально, колется «через несколько минут»,
  обычно проходит за 5–30 мин (бывали часовые простояния)
- **пустой пул `server10`** (`readyStreams:0`) — их очередь висит вечно,
  такие отправки мы пропускаем
- **Seedance 2.0 24/7** — пакетный доступ (135K / 265K / подписка), авто-рег
  его не даёт; нужен токен аккаунта с активным пакетом: файл
  `data/paid-token.txt` (`wtok_...`) или переменная окружения `PAID_TOKEN`.
  Без него Seedance-режим возвращает ошибку тарифа — текст покажем в интерфейсе
